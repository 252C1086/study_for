pythonはC言語やC++とは文法は似ているものの処理速度や変数の扱いについて大きな違いがあるため
今まで通りのプログラム理解のままでは学習を始められない。
ここでまずpythonにおけるオブジェクト参照について考える。

C/C++において
変数 -> メモリの特定のアドレスに付けられた名前
であるため、変数への値の代入はメモリへその値をコピーという操作になる。
一方Pythonはすべてがヒープ上に確保されたオブジェクトとして扱われるため
変数-> オブジェクトへのポインタ参照
になる。

例として、

ex)
a = [1, 2, 3]
b = a
b[0] = 99
print(a)

この.pyプログラムの実行結果は
[99, 2, 3] //aの出力結果
//bもb = [99, 2, 3]となっている
となる。

c言語の理解を適応して出力結果を予想すると

[1, 2, 3] //aの出力結果
//裏側でb = [99, 2, 3]となっている

であるため、プログラム2行目の「b = a」は値のコピーではなく、オブジェクトとして扱われるaをbへ参照(aと同じメモリアドレスを指すことになる)
とわかる。

つまり、pythonでの変数への代入や関数渡しはＣ言語でいうポインタの受け渡しと同義であると考えられる。

PyTorchにはtorch.Tensorがあり、Cの多次元配列(ex:a[3][3] -> 3 * 3の行列)
に似た構造を持つが、スマートな裏側の仕組みがある。

torch.Tensorによって準備したテンソルはどれだけ高次元であったとしても
1次元の連続したフラットな配列として格納される。
具体例無しではこの説明をつかむのは難しい。

例として2 * 3の行列のテンソルを準備する。
[0, 1, 2,
 3, 4, 5]
とする。

メモリ上ではこのテンソルは単純に
[0, 1, 2, 3, 4, 5]と配置される。
行を移動するとき(要素[0]->要素[3]へ移動)には要素を3つ飛ばす作業が必要である。
このとき、3は列数と一致する。
列を移動するとき(要素[0]->要素[1]へ移動)には要素を1つ飛ばす作業が必要である。
この作業は感覚的に明らかである。

この2つの作業をtorch.Tensorでは「ストライド」としてルール付けしている。
ストライド = (行の歩幅, 列の歩幅)
この例の中ではストライド -> (3, 1)
である。

このルール付けの強みの例として、行列の転置を考えると、C言語ではfor文などを使ってすべての要素を新しく用意したメモリ上へ
入れ替え後にコピーするという莫大な操作量を要する作業が必要だが、
PyTorchではストライドを逆転させるだけ(例として、stride(3, 1) -> stride(1, 3)とする)で転置行列を使用することができる。
よって、どんなに大きな行列を準備したとしても転置行列を呼び起こすときのけいさん時間はいつでもＯ(1)である。

※しかしよく考えると転置後は行方向の移動はメモリアクセスが不連続である。
　Ｃ言語で学習したメモリの局所性に近い。これは命令の実行時間にかなり影響するので、
　.contiguous()によって転置後の新しい形状に合わせてメモリを連続状態へ再配置することができる。

形状の異なる配列同士の計算はブロードキャスト(足りない次元をメモリを消費せずに仮想的に拡張して計算する仕組み)
によって一度に計算するため、Ｃ言語のようなfor文ループを回す必要がない。
